# FastAPI Effects 0.11.0a2

`0.11.0a2` is the corrected integration alpha from the quarter roadmap. It remains a
production-hardening prerelease, not a production-readiness or stable-v1 claim.

## What changed

- Relay, webhook transport, HTTP response, retention, and Taskiq operation budgets now
  reject invalid numeric types, NaN/infinity where applicable, booleans, and values
  outside their documented domains before runtime I/O.
- Real PostgreSQL T05 coverage exercises revoked and expired-retiring webhook keys,
  wrong-tenant access denial, interrupted terminal finalization, independent sibling
  progress, and immutable attempt accounting.
- Real PostgreSQL T09 coverage terminates backends at reconciliation, claim,
  tenant-session, and finalization boundaries. A protocol proxy drops a commit
  acknowledgement after PostgreSQL reports completion to exercise genuinely ambiguous
  outcomes, fencing, and retry identity.
- The release workflow must upgrade databases created and seeded by the exact public
  `0.11.0a1` PyPI wheel with the exact candidate wheel on PostgreSQL 16 and 18. It
  verifies data, ownership, runtime roles, grants, forced RLS, constraints, indexes,
  Alembic revisions, and component markers.
- The exact wheel and sdist-derived wheel run the selected recovery, signal, Taskiq,
  invoicing, webhook-receiver, and key-lifecycle journeys. PostgreSQL restart reports
  and every selected report are digest-bound into the release manifest.
- Consumer onboarding starts with an exact PyPI version and version-matched tag rather
  than a source build. Source-build commands are now a contributor appendix.
- The approved evidence ZIP, distributions, manifest, checksums, reports, SBOM, and
  conformance schemas are retained as GitHub release assets before trusted publication.

## Guarantees and limits

Application business state and original effect intent share one PostgreSQL transaction.
External delivery remains at least once. Automatic retry preserves delivery identity
and creates a new attempt; manual replay creates a linked delivery identity. A receiver
must perform durable business deduplication for one effective result.

The quarter's stable target is the PostgreSQL/SQLAlchemy transaction boundary, tenant
authority and forced RLS, fenced retry/replay, and signed-webhook journey. Taskiq,
command-idempotency, delegation, and FastMCP remain shipped provisional helpers with
mandatory security and recovery regression coverage.

Two independent deployments, independent security review, exact-RC observation, and
two-person stable approval are still absent. Those gates are deliberately not inferred
from this alpha's passing package and release evidence.
